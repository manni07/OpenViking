OpenViking Root-Test-Collection

Stand: 1. August 2026. Dieses Manual beschreibt die reproduzierbare Offline-Sammlung der Root-Tests. Es startet keine Services und fuehrt keine Provider- oder Live-Tests aus.

PASS: In einer frischen, aus uv.lock erstellten Worktree-Umgebung wurden 6384 Root-Tests ohne Collection-Fehler gesammelt.

2. Umgebung herstellen

cd /Volumes/ExtremePro/projects/OpenViking-agent-worktrees/20260801-root-collection-fix
UV_PROJECT_ENVIRONMENT=.venv-root-collect \
  uv sync --frozen --python 3.12.11 --extra test

Verifizierte Versionen: uv 0.8.20, Python 3.12.11, mcp 1.28.1 und scrapy 2.16.0.

3. Root-Collection ausfuehren

env -u GOOGLE_API_KEY -u OPENAI_API_KEY -u ANTHROPIC_API_KEY \
  -u OPENAI_ACCESS_TOKEN \
  .venv-root-collect/bin/python -m pytest \
  tests --collect-only \
  -q -o addopts= -p no:cacheprovider --no-cov --strict-markers

Erwartung: 6384 tests collected, Exitcode 0 und keine Collection-Fehler. Eine andere Zahl ist als Inventardrift zu untersuchen.

4. Was die Root-Collection absichtlich nicht besitzt

tests/api_test und tests/oc2ov_test sind eigenstaendige Harnesses mit eigenen Umgebungs- und Workflow-Vertraegen. Ihre Ausgrenzung bedeutet nicht, dass ihre Tests bestanden haben.

HOLD: Die Harness-Suiten selbst, die vollstaendige Root-Testausfuehrung, Gemini-/Provider-Live-Tests, H1 Capability-Probe und H2 Live-Benchmark/Canary wurden nicht ausgefuehrt. Fuer Live-Schritte ist eine neue ausdrueckliche Freigabe erforderlich.

5. Warnungs-Gate (aktualisiert)

Die zuvor offenen 11 cli_remote-, eine qdrant- und drei Helper-Class-Warnungen sind geschlossen. Die Marker sind registriert; die drei Supporttypen beginnen nicht mehr mit Test. Strict- und normale Collection melden keine Pytest*Warning.
